*Версия 2, 29.10.2026. Обновлена по вашим ответам. Статус: на согласовании, к реализации не приступаем.*

**Что изменилось после ваших ответов**
- **Аудитория:** приложение для всех. Основное ядро — женщины 18–35. Вторая целевая группа — стилисты и блогеры, которые собирают капсулы.

## 1. Суть идеи

**Вставил ссылку с WB/Ozon (или фото вещи) → видишь вещь на себе → собираешь из неё лук со своими вещами и вещами из других магазинов → решаешь, брать или нет.**

По вашим тестам: **Dressie (10/10)** — это «примерка по фото», **Acloset (10/10)** — «гардероб и луки». Мы объединяем оба продукта и делаем их под российские маркетплейсы.

## 3. Что мы решаем для пользователя

| Задача | Кто | Решение |
|---|---|---|
| «Как это будет на мне?» | все | Примерка на своё фото |
| «С чем это носить?» | все | Лук: новая вещь + гардероб + другие магазины |
| «Что выбрать из 5 вариантов?» | все | Сравнение рядом, «спросить подругу» по ссылке |
| «Собрать клиентке капсулу из WB» | стилисты, блогеры | Доска-лукбук, публичная ссылка, примерка на фото клиентки |
| «Какой размер брать?» | все | Советник по размеру (v2) |

Важное честное правило в интерфейсе: примерка показывает **образ** (цвет, фасон, сочетание), а **не точную посадку по размеру**.

## 4. Функционал

### 4.1. MVP
1. **Профиль и базовые фото.** 1–3 фото в полный рост с автопроверкой: видно всё тело, фронтальная поза, руки немного отведены, хороший свет, один человек. **Рекомендуем сниматься в облегающей одежде** (лосины/футболка в обтяжку) — без генеративного ИИ мы не можем «стереть» собственную объёмную одежду пользователя (см. 5.4).
2. **Добавление вещи:** ссылка WB/Ozon, артикул, скриншот или фото. На мобильных — «Поделиться» из приложения маркетплейса.
3. **Подготовка вещи (автоматически, на сервере):** выбираем лучший кадр, вырезаем вещь, определяем категорию и ключевые точки. Пользователь может выбрать другой кадр.
4. **Примерка на фото** с ручной докруткой: двигать, масштабировать, поворачивать; ползунки «длина», «ширина», «рукава»; «заправить/навыпуск».
5. **Лук из нескольких вещей:** слои в правильном порядке (низ → верх → верхняя одежда → аксессуары), перестановка слоёв.
6. **Цифровой гардероб:** фото своих вещей → автоудаление фона → категория, цвет, сезон (автоматически + ручная правка). Гардеробные вещи участвуют в луках.
7. **Луки и капсулы:** сохранить, переименовать, сгруппировать в капсулу, поделиться публичной ссылкой (режим стилиста).
8. **Вишлист** со ссылками «купить» на маркетплейс.

### 4.2. Версия 2
- Советник по размеру: размерная сетка + параметры пользователя + разбор отзывов.
- Отслеживание цены в вишлисте.
- «Спросить подругу» с голосованием.
- Live-AR режим через камеру (экспериментально).
- **Генеративный ИИ-режим «Реалистично»** как платная функция поверх того же интерфейса (раздел 5.6).

### 4.3. Позже
- Подборки «похожее дешевле», лента образов, B2B-виджет для брендов, кабинет стилиста с клиентами.

## 5. Примерка без генеративного ИИ

### 5.1. Важное уточнение
«Чистой математикой» без нейросетей найти на фото тело и вырезать одежду нельзя. Поэтому используем **бесплатные open-source модели распознавания** (они не рисуют новые картинки, а только находят точки и маски), а **саму примерку делаем математикой и графикой**:

| Задача | Инструмент | Лицензия | Где работает |
|---|---|---|---|
| Скелет (33 точки тела) | **MediaPipe Pose Landmarker** | Apache-2.0 | Браузер, iOS, Android, Python |
| Маски: волосы, лицо, кожа тела, **одежда**, фон | **MediaPipe Selfie Multiclass Segmentation** | Apache-2.0* | Браузер, мобильные, Python |
| Вырезание вещи из фона (гардероб, flat-lay) | **rembg + U²-Net / BiRefNet** | Apache / MIT* | Сервер (Python) |
| Деформация вещи | **Thin-Plate Spline (TPS)**, сетка | своя реализация | Сервер (OpenCV) + браузер (WebGL) |
| Рендер и ручная правка | **WebGL (PixiJS) / Canvas** | MIT | Браузер, WebView |
| Подгонка цвета и света | гистограммы, перенос цвета, мягкие тени | своя реализация | Браузер |

\* Перед релизом проверяем лицензию **каждой конкретной модели** по первоисточнику. Модели, обученные на исследовательских датасетах (SCHP/LIP/ATR, DeepFashion2), **не берём** — они некоммерческие.

### 5.2. Главная идея: «перенос с модели на человека»
Большинство фото на WB/Ozon — **вещь на модели**. Это удобно:
1. На фото товара находим **скелет модели** (MediaPipe Pose) и **маску одежды** (Multiclass Segmentation).
2. На фото пользователя находим **его скелет** и **маски** (тело, руки, лицо, волосы).
3. Строим соответствие точек «плечи модели → плечи пользователя», «локти → локти», «бёдра → бёдра» и т.д. и **деформируем вещь TPS-преобразованием**. Каждую часть деформируем отдельно: торс, левый и правый рукав, штанины — так меньше искажений.
4. **Компоновка слоёв:** кожа и руки пользователя там, где они должны быть поверх вещи; волосы поверх воротника; вещь поверх собственной одежды.
5. **Подгонка под свет фото пользователя:** яркость, баланс белого, мягкая тень по краям.

Для **flat-lay** (вещь на белом фоне или вешалке) точки находим по контуру маски вещи (плечевые углы, проймы, низ) с заготовленными шаблонами для каждой категории: футболка, рубашка, куртка, брюки, юбка, платье.

### 5.3. Где что считается
- **Подготовка вещи — на сервере, один раз на товар:** вырезка, точки, категория → кэш. Одну вещь примеряют тысячи людей, считаем её один раз. Это публичные данные, без персональных данных.
- **Фото пользователя и сама примерка — на устройстве, в браузере** (MediaPipe через WebAssembly/WebGL).
  - Почти нулевая стоимость серверов.
  - Мгновенный отклик и ручная правка в реальном времени.
  - **Фото по умолчанию не покидает устройство** → сильный аргумент приватности и проще с 152-ФЗ.
  - Синхронизация фото и гардероба между устройствами — **по согласию пользователя**, с хранением в РФ.

### 5.4. Честные ожидания по качеству (без ИИ)

| Хорошо | Средне | Плохо |
|---|---|---|
| Футболки, лонгсливы, рубашки, свитеры, пиджаки, куртки во фронтальной позе | Брюки и джинсы, юбки, платья приталенные, верхняя одежда оверсайз | Платья-клёш, длинные пальто, сильно отличающиеся позы, руки перед телом, своя объёмная одежда пользователя |

Из этого следуют решения по продукту:
- Онбординг учит делать **«правильное базовое фото»**: облегающая одежда, фронтально, руки чуть в стороны.
- **Ручная докрутка** — штатная функция, а не костыль. Это заодно режим «коллажа» для стилистов (как в Combyne/Whering).
- **Метка уверенности:** если автоподгонка вышла плохо (большое расхождение поз), предлагаем «Режим коллажа»: вещь рядом с фото, а не на нём.

### 5.5. Обязательная проверка до разработки (этап 0)
Прототип конвейера на **50 реальных товарах WB/Ozon × 10 разных фото людей**. Слепая оценка «приемлемо/нет» по категориям.
- **Точка решения:** если приемлемо **меньше 50%** в ключевых категориях (верх), раньше планируем генеративный режим или сужаем MVP до категорий, где работает хорошо.

### 5.6. Разъём для ИИ в будущем
Примерка — это интерфейс `TryOnEngine` с реализациями:
- `overlay` (сейчас),
- `vton_selfhosted` (FASHN VTON v1.5, Apache-2.0, на GPU в РФ),
- `vton_api` (FASHN/Kling).

Данные (вырезанные вещи, точки, фото пользователя) уже лежат в нужном формате, поэтому ИИ добавится без переделки продукта.

❌ Модели CatVTON, IDM-VTON, OOTDiffusion — некоммерческие, не используем ([сравнение лицензий](https://fashn.ai/blog/comparing-the-top-4-open-source-virtual-try-on-viton-models), [список по лицензиям](https://github.com/XQ0820/open-virtual-try-on-models)).

## 6. Данные с маркетплейсов

- **WB:** публичные JSON-эндпоинты карточки и CDN картинок по артикулу (`card.wb.ru`, `basket-XX.wbbasket.ru`). Неофициально: формат меняется.

- **Устройство:**
  - Слой коннекторов по маркетплейсам + кэш карточек и обработанных вещей.
  - Ежедневный автотест на эталонных артикулах: узнаём о поломке раньше пользователей.
  - **Всегда работающий запасной путь:** скриншот или фото → примерка работает, даже если парсер сломан.
- **Проверить партнёрские программы** WB/Ozon/Lamoda — легальные ссылки «купить» и основной доход на старте.
- Изображения товаров используем только для примерки пользователя, публичный каталог из них не делаем.

## 7. Технологии (моё решение)

### 7.1. Структура: монорепозиторий
```
apps/landing        — лендинг (Next.js, статическая сборка): SEO, лист ожидания
apps/web            — приложение: React + Vite + TypeScript + Tailwind, PWA
packages/tryon      — движок примерки на TS: MediaPipe Tasks Vision, TPS, WebGL-рендер
                      (один и тот же код в браузере и в мобильной обёртке)
services/api        — Python + FastAPI: аккаунты, гардероб, луки, капсулы, публичные ссылки
services/worker     — Python: парсинг маркетплейсов, подготовка вещей
                      (MediaPipe, rembg/BiRefNet, OpenCV)
infra               — Docker Compose; PostgreSQL, Redis + очередь (arq), S3 в РФ
```

### 7.2. Почему так
- **FastAPI + Python** — ваш выбор, подтверждаю: вся обработка изображений и будущий ИИ на Python.
- **Движок примерки на TypeScript в клиенте:** бесплатная работа, приватность, интерактивность.
- **Хостинг в РФ** (Selectel / Yandex Cloud / Timeweb): данные пользователей по 152-ФЗ. На старте хватит одного VPS без GPU.

### 7.3. Мобильные приложения: **Capacitor, не Flutter**

| | Capacitor | React Native | Flutter |
|---|---|---|---|
| Переиспользование кода PWA и движка примерки | ~90% | частично (движок придётся адаптировать) | 0%, всё заново на Dart |
| MediaPipe | тот же веб-код | нативные модули | сторонние плагины |
| Время до сторов | 2–4 нед | 2–3 мес | 3+ мес |

Движок примерки работает на WebGL и WASM, а Capacitor запускает тот же код внутри приложения. **Flutter означал бы переписать самое сложное — движок.** Если когда-то упрёмся в производительность, переносим горячие места в нативный плагин Capacitor.

**Почему нативная обёртка нужна достаточно рано:**
- Главный сценарий — «Поделиться» из приложения WB → в наше приложение.
- **На iOS PWA не может принимать «Поделиться».** На Android работает частично (Web Share Target).

**Сторы в РФ:** RuStore + Google Play + App Store. Оплаты (позже) — через веб (ЮKassa/CloudPayments), так как встроенные покупки App Store для РФ проблемны.

## 8. Право и безопасность

- **Фото пользователя — персональные данные.** Мы **не используем их для идентификации**, поэтому это не биометрия. Обработка по умолчанию на устройстве, на сервер — только по согласию; хранение в РФ.
- Согласие на обработку ПДн, политика конфиденциальности, пользовательское соглашение.
- **Запрет:** чужие фото без согласия, фото несовершеннолетних; примерка белья и 18+ недоступна. Публичные ссылки на луки — без фото пользователя по умолчанию (только вещи), фото — по явной галочке.
- Удаление всех данных одной кнопкой.

*Это не юридическая консультация — перед публичным запуском нужна проверка юристом.*

## 9. Монетизация

Без генеративного ИИ себестоимость примерки ≈ 0 → **щедрый бесплатный тариф** для роста.

1. **Старт: партнёрские ссылки** на маркетплейсы (комиссия с покупок после примерки).
2. **Pro-подписка** (~199–299 ₽/мес), когда появится ценность сверху: безлимитный гардероб, капсулы и лукбуки для стилистов (брендированные ссылки, клиенты), советник по размеру, **ИИ-режим «Реалистично»** (платный из-за GPU).
3. **Позже B2B:** виджет примерки и луков для брендов и продавцов.

| **1. MVP-ядро (PWA)** | 5–6 нед | Онбординг фото, примерка по ссылке/фото, ручная докрутка, история, вишлист |
| **2. Луки и гардероб** | 4–5 нед | Многослойные луки, гардероб с автовырезкой, капсулы, публичные ссылки для стилистов. **Закрытая бета** 100–300 человек (в т.ч. 10–20 стилистов) |
| **3. Мобильные приложения** | 3–4 нед | Capacitor-сборки, приём «Поделиться», публикация в RuStore / Google Play / App Store; коннектор Ozon |
| **4. Рост и ИИ** | далее | Советник по размеру, цены, «спросить подругу», платная подписка, генеративный режим |

Лендинг с листом ожидания запускаем **на этапе 0**, чтобы к бете была аудитория.

**Метрики MVP:**
- ≥ 60% примерок «приемлемо» по оценке пользователей (для верха — ≥ 70%).
- Время до первой примерки < 2 минут.
- Retention D7 ≥ 20%.
- ≥ 1 сохранённый лук на активного пользователя.
- CTR «купить».
- Для стилистов: ≥ 30% из беты создали капсулу и поделились ею.
